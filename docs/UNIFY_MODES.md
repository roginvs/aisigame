Связанный пункт в [to-do.md](../to-do.md): стол как конференция остаётся отложенным; места в конференции закрыты здесь.

## Сделано 24 октября 2026

Контроллер отличает места по `player.id`, не по устройству. Ведущая и подписи хода берут имя этого игрока (`playerName` / `conferenceTurnTitle`). Очки по-прежнему меняет только машина.

- Несколько `Player` с одним `clientId`. `ADD_PLAYER` отбрасывает повтор того же id, не второе место устройства.
- Поле имён конференции — несколько имён (`;` или новая строка). Пустое нельзя. `hello` шлёт `names` и подпись `name` («Аня, Боря»). Старый hello только с `name` — одно место, чтобы не рвать уже открытую вкладку. Отдельный `protocolVersion` не вводили: версия сборки по-прежнему `commit`.
- `buzz`, скрытая ставка и печатный ответ финала несут `playerId`. Мастер принимает его, только если место принадлежит `clientId` отправителя. Одно место без `playerId` работает как раньше. Кот и аукцион: `actorId` — кто нажал; без поля и при одном месте это единственное место.
- Апелляция и автоапелляция позднего транскрипта уже были по `playerId`. Чужое место того же устройства очки не получает и чужие не отбирает.
- `ready`, пакет, stale и камера — на устройство. Все места отключившегося устройства уходят вместе; ход не переходит другому месту того же `clientId`.
- Состав мест после выдачи id не пересаживается новым hello (в том числе другим порядком имён). Новые люди — новый `clientId` и поздний вход.
- Финал: у каждого финалиста своё поле, если это место устройства. Суммы по-прежнему скрыты от других устройств. Два человека у одного экрана видят поля друг друга — как за общим столом.
- Клавиши конференции — по порядку местных мест: 1 — пробел; 2 — левый и правый Ctrl; 3 — левый Ctrl, пробел, правый Ctrl; с четвёртого только кнопка. На телефоне Ctrl нет: жмут кнопки карточек. За столом клавиши прежние (глобальные 1/2/3).
- Общий микрофон устройства не делится по голосам. Уровень речи во время хода приписывается тому месту устройства, чей сейчас ход.

Не сделано и не требуется для мест: прегейм стола, микрофон стола «как онлайн», общий ряд карточек стола.

## Цель

Режимы максимально похожи. Отличие по сути:

| | За столом | Конференция |
|---|---|---|
| Jitsi / Bridge Channel | нет | есть |
| Камера | кнопок cam нет | mic · cam · next |
| Микрофон панели | в сессию модели | в Jitsi (+ микс в модель у мастера) |
| Звук ведущей | локально из сессии модели | мастер локально + бот в Jitsi; joiners через Jitsi `<audio>` |
| Пульс рамки портрета | уровень локального выхода модели | уровень бота «Ведущая» из Jitsi |
| Несколько имён на устройстве | да | да (общий mic/cam/endpoint) |
| Текстовый чат | нет (некому писать) | да, подпись «Чат · А, Б» |

Всё остальное — общий путь (машина, кнопки, выбор, оценка, фазы, подписи хода, solo-listen, раскладка карточек).

## Модель: несколько игроков на одном устройстве

- Один браузер / один `clientId` / один Jitsi endpoint (в конференции) / один mic / одна cam.
- Несколько `Player` с **одним** `clientId`.
- У каждого своя карточка и своя кнопка; cam / mic-индикатор / speaking **дублируются** на все карточки устройства.
- Клавиши — по порядку **локальных** мест (не по глобальному id).
- `buzz` несёт `playerId` нажатой кнопки; мастер принимает только если игрок принадлежит `clientId` отправителя.
- Клик по полю: устройство может кликать, если `chooserId` — кто-то локальный; «кто ткнул» = текущий chooser (различить пальцы нельзя).
- `ready` / heartbeat / stale / `CHOOSER_OFFLINE` — по **устройству**.
- На ходе А модель слышит весь mic устройства (Б рядом тоже) — так и оставляем.

Пример: А+Б на ноутбуке мастера, В+Г на планшете → два `clientId`, четыре игрока.

## UX

### Старт / join

- Конференция (мастер и join): textarea имён; пустое **нельзя** — хотя бы одно имя.
- За столом: как сейчас (пустое → трое по умолчанию).
- Подсказка: имена через `;` или с новой строки — своё и остальных за этим устройством.
- Jitsi URL — только конференция.
- Jitsi `displayName` устройства: «А, Б».

### Раскладка

Общий каркас PLAYOUT (две колонки). Стол без cam/next и без compose чата; конференция с cam и чатом.

Подписи хода («Вася выбирает вопрос», «Слушаю Вася») — **оба** режима.

### Клавиши

| Локальных | Клавиши |
|---|---|
| 1 | Пробел |
| 2 | Левый Ctrl, правый Ctrl |
| 3 | Левый Ctrl, пробел, правый Ctrl |
| 4+ | Как у троих для первых трёх; остальные только экран |

Enter не используем.

### Микрофон

- **Конференция:** как сейчас (панель → Jitsi; микс; пауза глушит).
- **Стол:** прегейм → «Начать игру» → запрос mic + старт партии; панель mute как онлайн; пауза глушит; контроллер по фазам тот же; пульс портрета с локального host stream.

### Лобби конференции при multi-seat

- Мастер «А; Б» → сразу две готовые карточки, один clientId.
- Joiner: один `hello` с `names[]` + согласованная версия протокола (см. проверку версий ниже); один `ready` на устройство.
- Прогресс пакета / «готов» отражаются на всех карточках устройства (дубли статуса); кнопка «Я готов» одна на устройство (на локальной группе).
- Несовместимая версия клиента с мастером → отказ, понятная ошибка («обнови страницу»). Обратной совместимости со старым протоколом нет.

## Протокол (конференция)

1. `hello`: `names: string[]` + согласованный контракт версии; текущая сверка commit уже есть, дополнительный protocolVersion определяем ниже.
2. Roster: N игроков на один `clientId`.
3. `START_GAME` / mid-game `ADD_PLAYER`: по игроку на имя.
4. `buzz`: + `playerId` (проверка принадлежности к clientId).
5. `pick`: ok, если chooser на этом clientId.
6. Снимки / restore: несколько игроков с одним clientId.

## Решения до кода и границы этапов

1. **Устойчивая идентичность места.** Определить seatId либо неизменяемый индекс в списке устройства. Имена не ключ: возможны совпадения и переименование. При reload сохранить связь с playerId и очками; изменение порядка/числа имён после старта не должно пересаживать игроков. До поддержки редактирования безопасный вариант — состав мест после допуска неизменяем, новые люди только через явно описанный поздний вход.
2. **Отключение устройства.** Все его места одновременно stale/hidden. Handoff не должен передать ход другому месту того же отключённого устройства; выбирать из игроков других живых и проверенных устройств. Активный ответ и ставка завершаются штатным таймаутом. Финалисты уже собраны: поздний вход не дописывает их молча.
3. **Кеш/ready и восстановление.** Один hello/ready/peer/запрос пакета на устройство; повтор ready не добавляет места заново. Продолжение мастера восстанавливает все места/очки/историю до первого snapshot. Reload гостя с новым endpoint сохраняет секрет и места, но заново сверяет пакет. Кеш есть/нет, закрытый канал и отказ разбора — отдельные сценарии.
4. **Версии.** Текущая сверка commit уже реализована (`buildMatch.ts`); dev обычно имеет `dev`, поэтому сама по себе не гарантирует одинаковую схему двух dev-сборок. Если вводится protocolVersion, задать один контракт для hello и состояния, ошибку и путь обновления. Не путать с savedGameVersion; старые сохранения можно мигрировать даже при отказе старым сетевым клиентам.
5. **Стол без транспорта.** Общий UI не должен создавать Jitsi, roster сетевых endpoints или обращаться к undefined clientId. Мute панели пользователя отделить от фазового setMicEnabled контроллера; пауза/RESUME сохраняют выбор пользователя. Сохранить continue собственного файла, model switch, media autoplay и debug. На нескольких местах за столом модель не может из общего mic физически выделить голос одного человека.
6. **Порядок.** Сначала общий UX стола с регрессиями; затем устройство/места и стабильное сохранение; после этого wire/валидаторы/master/joiner, UI/клавиши и медиа. При необходимости несколько коммитов в одной ветке; не публиковать смешанный несовместимый протокол как готовый этап.

## Дополнительная приёмка

- Одинаковые имена, пробелы/пустые строки и недопустимый names[]; не гадать место по тексту имени.
- Два места мастера и два гостя: отдельные id/очки/кнопки, одна камера/передача, ready один; чужой и неизвестный playerId в buzz отклоняются.
- Перехват после ошибки одного локального места другим: missedIds/фальстарт относятся к игроку, не к устройству. Одновременные кнопки решает первое событие машины.
- Reload гостя и мастера, старый одиночный снимок, новый многоместный снимок, сохранение двух разных счетов одного устройства и повтор hello без дублей.
- Stale/hidden всего устройства и handoff с пропуском всех его мест; продолжение на паузе и поздний вход во время финала.
- Финальные ставки/ответы двух мест одного устройства с hearTurnOnly; звук других людей в HTML не глушится.
- 1/2/3/4+ локальных места, глобальные id не 1/2/3, ввод чата не нажимает кнопку; 390×844 и desktop.
- Реальные устройства Jitsi дополнительно к BroadcastChannel: последний не проверяет WebRTC, разрешения mic/cam и мобильный звук.
