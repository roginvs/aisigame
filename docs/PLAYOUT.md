# План раскладки конференции (playout)

Цель: убрать правую видеополосу Jitsi, перенести камеры и статусы игроков в зону кнопок, а локальные медиа-кнопки и «Начать игру» — в подвал колонки «Разговор», над полем чата. Режим «За столом» не трогаем.

Статус: **реализовано в UI** (полировка автором локально). Дефолты из «ещё открыто» взяты как в плане.

### Экраны

- **Широкий десктоп:** viewport locked (`100dvh`), табло + ряд игроков в колонке play, чат с внутренним скроллом и закреплённым подвалом (mic/cam/compose).
- **≤1100px (планшет/телефон):** страница **вертикально скроллится** целиком (`main.table` → `height: auto; overflow: visible`). Нельзя оставлять `overflow: hidden` на `.layout` / `.talk` / `.conference-layout .play` с долями `fr`/`28%` — иначе обрезаются статусы и нельзя доскроллить до «Я готов» / чата. Ряд участников на ≤900px — горизонтальный скролл плиток, без бокового скролла всей страницы.
- Проверять моком `?mock=1&transport=broadcast`: 1–5 участников, ширины ~390×844, ~768×1024 и десктоп; e2e — `e2e/mobile-conference.play.ts`.

## Целевая раскладка

Две колонки (без правого strip):

```
┌──────────────────────────────┬──────────────────────────┐
│ stage                        │ HostPresence             │
│  лобби: один глобальный      │ Разговор (лента)         │
│         статус ожидания      │                          │
│  партия: поле / вопрос       │                          │
├──────────────────────────────┤  [мастер, лобби:         │
│ players / video row          │   Начать игру на всю     │
│  камера · имя · mic · речь   │   ширину чата]           │
│  лобби / ещё не в игре:      │  [у ВСЕХ, в т.ч. мастер: │
│    полоска + прогресс        │   Мик · Камера · След.]  │
│    у себя: «Я готов»         │  [поле чата · Отправить] │
│  партия (уже играет):        │                          │
│    счёт · buzzer · подсказка │                          │
└──────────────────────────────┴──────────────────────────┘
```

### Подвал чата (над compose) — решено

Порядок сверху вниз:

1. **Только мастер, только лобби:** кнопка «Начать игру» на всю ширину колонки чата.
2. **Все участники конференции, включая мастера** (лобби и партия): одна горизонтальная полоска — микрофон, камера, следующая камера (последняя — как сейчас: пока камера включена / с учётом `mediaBusy`). У мастера этот ряд **есть всегда**, не вместо «Начать игру», а **под** ним в лобби и один в партии.
3. Поле сообщения и «Отправить» — без изменений по смыслу.

У joiner пункта 1 нет. После старта партии пункта 1 у мастера тоже нет; пункт 2 остаётся.

Кнопки mic/cam с видеоплитки убираем — только этот ряд. Индикатор «мик выкл.» / `mic-live` / speaking на плитках остаётся.

### Зона игроков (бывший `.players`) — решено

Ряд виден и в лобби, и в партии. Сюда переезжают камеры из strip **и** бывшие roster-статусы загрузки / готовности.

На каждой карточке всегда:

- кадр камеры или placeholder (в лобби — полное имя; в партии при выкл. камере — «камера выкл.»);
- имя **один раз** (лобби — в кадре; партия — в строке счёта, не в кадре и не на buzzer);
- индикатор выключенного микрофона (оверлей на кадре);
- золотой пульс рамки при `speaking`.

Ниже камеры — **слот статуса**, взаимоисключающий по фазе участника:

| Когда | Что в слоте |
|---|---|
| Лобби или человек ещё не допущен к игре (качает / не сверил / mid-game joiner до hash) | Полоска прогресса + `packProgressLabel` (%, скорость, ETA, «Сверка…», «Пакет сверен», «готов»). У **своей** плитки joiner — ещё кнопка «Я готов» (disabled до `hashOk` / после `readySent`), на месте где в партии будет buzzer. У мастера в лобби прогресса нет (он уже 100% / готов) — слот можно оставить пустым или короткой меткой «мастер», без полоски. |
| Партия, игрок уже в машине | Имя + счёт + buzzer («выбирайте вопрос» / «Уже отвечал» / «Жмите» / фальстарт) + подсказка «Пробел» у себя. Прогресс и «Я готов» не показываем. |

Смысл: прогресс и «Я готов» живут ровно там, где потом появятся игровые статусы — одна вертикальная колонка на человека, без второй панели.

Связка плитки с игроком: по `clientId` / локальной плитке; «Ведущая» не плитка. `hiddenClientIds` — карточка пропадает. Mid-game joiner до сверки: на его карточке прогресс вместо buzzer; после `ADD_PLAYER` — обычный игровой слот.

### Зона табло в лобби

Вместо `ConferenceRosterPanel` — **одна короткая глобальная строка**:

- «Ждём начала игры»
- «Ждём мастер-игрока» (`waitingMaster`)
- «Мастер-игрок отключился» (`masterOffline`) — баннер над табло в лобби и в партии (поле/вопрос/загрузка пакета), дубль красной строкой у портрета

Персональный прогресс с табло уходит — он на карточках в ряде игроков.

После `START_GAME` здесь снова поле / вопрос.

## Что сохраняем без переноса смысла

- Портрет ведущей, фазы, solo-listen hint, `mediaError` у портрета.
- Лента «Разговор» + текстовый чат.
- Шапка: ссылка, выход, дебаг; у мастера — модель, токены, AirStatus, пауза, пропуск раунда.
- Логика Jitsi / микс / `setModelHearOnly` — только UI.
- Режим «За столом»: без strip и без медиа-ряда в чате.

## Аудит правой панели (`ConferenceVideoStrip`)

Это **единственное**, что рисовала убираемая колонка. Источник: `ConferenceVideoStrip.tsx` + стили `.video-strip` / `.video-tile`. Ведущая в плитки не входила и не входит.

| # | Что показывали / делали | Где было | Куда в новом плане | Ок? |
|---|---|---|---|---|
| 1 | Живое видео участника (`<video>`, `bindVideo`, если `cameraOn`) | плитка strip | плитка в ряде `.players` | да |
| 2 | Placeholder: в лобби полное имя; в партии «камера выкл.» (имя уже в счёте) | кадр плитки | тот же кадр в `.players` | да |
| 3 | Имя в meta кадра | meta плитки | лобби при вкл. камере — оверлей; в партии — только `player-meta`, без дубля | да |
| 4 | Метка «мик выкл.» + классы `mic-live` / `mic-off` | meta плитки | meta плитки в `.players` | да |
| 5 | Золотой пульс рамки при `speaking` | CSS плитки | та же анимация на карточке в `.players` | да |
| 6 | Список всех человеческих участников (локальный + remote), без бота «Ведущая» | весь strip | тот же набор плиток в `.players` (лобби и партия) | да |
| 7 | Кнопка микрофона: подпись вкл/выкл, `aria-pressed`, `disabled` при `mediaBusy` | только на **своей** плитке | ряд над compose в чате у **всех ролей, включая мастера** | да |
| 8 | Кнопка камеры: то же | своя плитка | тот же медиа-ряд в чате | да |
| 9 | «Следующая камера» только пока камера включена, `mediaBusy` | своя плитка | тот же медиа-ряд в чате | да |
| 10 | `aria-label="Участники"` у контейнера | `<aside class="video-strip">` | перенести на ряд игроков / его обёртку | да (не забыть в коде) |
| 11 | Узкий экран: горизонтальный скролл плиток | CSS strip | тот же паттерн на ряде `.players` | да |

**Не было в правой панели** (и не должно «пропасть из strip» — его там не было): прогресс пакета, «Я готов», «Начать игру», счёт, buzzer, ошибка медиа (`mediaError` уже у портрета), речь ведущей (портрет). Их перенос описан отдельно в общем инвентаре.

**Единственное изменение формы, не содержания:** кнопки 7–9 снимаются с локальной плитки и стоят одной строкой над чатом. Состояния и действия те же; визуально они больше не «приклеены» к своей камере.

Вывод аудита: из правой панели **ничего не теряется** — кадры и статусы речи/мика едут в ряд игроков, управление медиа — в подвал чата.

## Шаги реализации

1. CSS: `conference-layout` → две колонки; `.video-strip` как колонку убрать.
2. `ConversationChat`: над compose — опциональная «Начать игру» (мастер+лобби) **и всегда** медиа-ряд для конференции.
3. Карточка игрока: видео без локальных controls + слот статуса (lobby progress / ready vs score / buzzer).
4. Лобби-stage: простой глобальный статус вместо `ConferenceRosterPanel`.
5. Адаптив: горизонтальный скролл ряда игроков; sticky compose сохранить.
6. Тесты и e2e при съехавших селекторах.
7. После кода: `ONLINE.md` §Лобби, `AGENTS.md`, `CONTEXT.md`, этот файл — done.

Логику сессии, presence, pack transfer и confirm мастера при неготовых гостях **не меняем** — только где это рисуется.
