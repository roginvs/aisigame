# Раскладка: текст вопроса всегда виден

Жалоба: игроку не было видно вопрос, на большом мониторе — видно. Причина (воспроизведено e2e `e2e/question-fit.play.ts`):

1. **Широкий (>1100 px CSS) и короткий экран.** Карточка вопроса там фиксированной высоты с `overflow: hidden` (чтобы картинка занимала остаток), а `<h2>` мог сжиматься (`flex: 0 1 auto; min-height: 0`) — длинный текст просто обрезался снизу. Это ноутбуки: 1280×720, 1280×800, 1440×900, 1366×768 (вопрос ~450 символов), 1536×864 и 1920×1080 с масштабом Windows/браузера 125–150 % (в CSS-пикселях окно ~1229×600 и ~1280×640), а также низкое окно браузера. Даже демо «Текст, 200» резался на 1280×720 и на 1536×864 с зумом 125 %.
2. **Конференция.** Кадр камеры 4:3 по ширине карточки игрока (до 400 px) давал ~300 px видео, и ряд игроков забирал почти всю высоту: на 1536×864 с зумом 125 % гостю оставалось ~90 px под вопрос — видно две строки.

Узкие экраны (≤1100 px: телефоны, планшеты, 1366×768 с зумом 125 %) не ломались: там страница прокручивается, карточка растёт по тексту.

## Как теперь

- `src/ui/questionFit.ts` (`useFitQuestionText`): если текст не помещается в своём блоке, шрифт уменьшается двоичным поиском до `questionFit.minFontPx` (18 px, `options.ts`); не влез и так — у `<h2>` класс `question-text-scroll`, текст листается внутри карточки (тонкая полоса прокрутки). Пересчёт при смене текста, размера карточки/окна и после загрузки шрифтов. Картинка/видео получают остаток, как раньше (`min-height` медиа сохранён).
- Конференция: ширина карточки игрока ≤ `26dvh·4/3`, то есть кадр не выше 26 % высоты окна (`.players.conference-players > .conference-player`).
- Мастер и гость рендерят один и тот же `GameScreen`, поэтому правка одна для всех.

## Проверка

`npx playwright test e2e/question-fit.play.ts` — 11 размеров (ноутбуки с зумом, низкое окно, планшет, телефоны), вопрос ~450 символов, вопрос с картинкой, огромный (~1800 символов — прокрутка) и гость в конференции. `SCREENSHOT_DIR=/workspace` кладёт снимки в `/workspace/layout-after-*.png`.
Размеры экрана игрока теперь есть в дебаг-дампе (`[экран]`, docs/DEBUG.md): по ним можно задать такой же `viewport`/`deviceScaleFactor`.
