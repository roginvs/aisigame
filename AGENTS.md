# AGENTS.md — правила работы агента

Браузерная викторина «Своя игра» с голосовой AI-ведущей. Стек: React + TypeScript + Vite + XState 5; партии из пакетов `.siq`; голос — Realtime API (OpenAI/xAI/Google/Qwen/мок); онлайн через Jitsi; локальный режим «за столом». Репозиторий: https://github.com/roginvs/aisigame, сайт: https://roginvs.github.io/aisigame/.

## Обязательные правила

1. **Конкретная задача — не аудит репозитория.** По просьбе «исправить X» правь только X: без общего осмотра кода, чтения всех документов и реорганизации несвязанных мест. Полная сверка проекта и документации — только по явной просьбе.
2. **Читать только нужное.** Открой профильный документ задачи (карта ниже) — и в нём только затронутый раздел по оглавлению вверху файла или Grep-ом по заголовку. Большие документы и архив целиком не загружай.
3. **Обновлять точечно.** После задачи обнови затронутый раздел профильного документа и свой пункт `to-do.md`. Датированные решения («N октября …») пиши в профильный документ задачи, не сюда; AGENTS.md меняется, только когда изменились правила, карта, команды или термины. Этот файл не вести как журнал.
4. **Термины ровно эти:** **контроллер** — машина состояний на устройстве мастера (`src/game/machine.ts` + `controller.ts`), держит главное состояние, модель, микшер и дорожки, людям ничего не показывает; **мастер** — игрок за тем же компьютером (экран из полученного состояния + свои кнопки управления); **игрок** — любой участник, кроме мастера. **Главное состояние** — только оно управляет логикой; **полученное** — только отображение, строится из снимка одним путём у всех (игроки — из транспорта, мастер — петля `LoopbackStateReceiver`). Действия мастера идут прямо в контроллер, игроков — сообщениями Jitsi; те и другие — одни события контроллера. Не называть контроллер «мастером». Подробнее — «Термины» в [docs/ONLINE.md](docs/ONLINE.md).
5. **Модель не правит счёт.** Очки меняет только XState; модель меняет счёт только через function calling, аргументы проверяет машина. React не хранит правила: `src/ui` — только отображение и клики. Куда класть код — карта ниже и «Куда класть код» в архиве.
6. **Границы связи.** Backend не добавлять, пока прямой вызов из браузера сам не откажется. Ключ API не писать в код, `.env`, логи, тесты и README.
7. **Качество.** Типы строгие (`strict`, `noUncheckedIndexedAccess`), eslint запрещает `any` и `[object Object]` в шаблонных строках; глушить правила директивами нельзя — чини тип. Перед отчётом: `npm test` (включает lint) и `npx tsc -b`; экраны/графика — e2e `npm run look`.

## Эффективная работа AI-агента и экономия контекста

Дополнение к правилам 1–3: качество работы важнее экономии, она не должна снижать качество исправлений, нарушать требования проекта или пропускать нужные проверки.

- Архивы, исторические отчёты и старые изменения не читать без прямой необходимости: история выполненных задач — не рабочий контекст.
- Работая над задачей из `to-do.md`, не изучай весь список — только её пункт.
- Не перечитывать уже изученные файлы без причины; искать по конкретным функциям, строкам и заголовкам.
- Обновлять только задетую документацию, без длинных исторических отчётов о каждой правке.
- Не дублировать технические решения в разных документах — в остальных местах ссылка на основной источник требований.
- Не затягивать предварительный анализ: когда информации достаточно — правь и проверяй результат.
- Большие задачи делить на небольшие законченные этапы, сохраняя промежуточные результаты.

## Команды

```bash
npm install
npm run packs     # демо-пакет: packs/demo.xml → public/packs/builtin/demo.siq
npm run dev       # 127.0.0.1:5173, слушает сеть (планшет); ?mock=1 — мок без ключа
npm test          # lint + unit-тесты
npx tsc -b
npm run look      # Playwright e2e; порт — AISIGAME_TEST_PORT
npm run build     # production, base /aisigame/ (для Pages)
```

Push в `master` гоняет CI (`.github/workflows/ci.yml`: `npm ci`, `npm test`, `npx tsc -b`) и публикует сайт (`.github/workflows/pages.yml`).
