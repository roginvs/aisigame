# Инструкции для агентов

Этот файл — короткая рабочая память проекта. Его нужно обновлять при каждой существенной правке: что сделано, что решили, как запускать, какие ограничения ещё действуют.

Полный контекст лежит в `docs/CONTEXT.md`: исходное техническое задание, исследование API, договорённости из обсуждения и текущий статус. Схема партии, как она идёт сейчас, лежит в `docs/GAME.md`. Любое изменение логики партии или состояний машины после этого обновляет `docs/STATES.md`: состояния, переходы, условия и что при этом происходит, чтобы карта не расходилась с кодом. Отложенные задачи — в [to-do.md](to-do.md). Перед работой прочитай их и этот файл. После работы обнови их, если изменились решения, объём прототипа или известные проблемы.

`docs/CONTEXT.md` тоже нужно обновлять постоянно. Не оставляй важные договорённости только в чате.

Когда задача по сути закончена (код/правки на месте, проверки прошли или дальше ждать нечего) — один раз проиграй готовый сигнал «беее» из репозитория, без генерации на лету и без правок игры:

```bash
paplay scripts/agent-done.wav
```

Файл — `scripts/agent-done.wav` (короткое блеяние). Не коммитить ради одного проигрыша; не подменять другим звуком без просьбы. Если `paplay` нет — тихо пропусти, текст ответа не раздувай.

Игра — этот репозиторий. Каталог раньше лежал в `playground/aisigame` и скопирован сюда без истории того git. Канонический remote: https://github.com/roginvs/aisigame. Локальный путь: `~/aisigame`.

## Сейчас

Прототип уже запускается: связь, машина, пакет вопросов, несколько раундов и финал.

Раскладка конференции (см. [docs/PLAYOUT.md](docs/PLAYOUT.md)): две колонки без правого video-strip; камеры, прогресс пакета и «Я готов» в ряде игроков; «Начать игру» у мастера и mic/cam/next у всех над чатом.

План сближения «За столом» и «Конференция» + несколько игроков на одном устройстве: [docs/UNIFY_MODES.md](docs/UNIFY_MODES.md) — решения закрыты, код ещё не начат. Порядок: сначала стол как конференция по UX, потом multi-seat.

В партии 10 секунд без heartbeat делают онлайн-игрока `stale`. Если он в этот момент выбирает ячейку или тему финала, мастер шлёт `CHOOSER_OFFLINE`: XState передаёт `chooserId` следующему по кругу подключённому игроку, а ведущая свободно объявляет отключение и нового выбирающего (`hostCue`: кто ушёл, кто теперь выбирает, ячейка или тема финала). Во время ответа presence не меняет игрока: ждём штатные `answerMs` / `judgeMs`. В `choosing.*` клик/сообщение `pick` принимаются только от `chooserId`. Микс для модели в `choosing.*` и `answering.*` сужается до выбирающего или отвечающего (HTML/Jitsi playback людей не глушится); если Jitsi id ещё нет — fail open на всех. В окне кнопки и остальных фазах микс по-прежнему общий. В карточке ведущей тогда строка «Никого другого не слушаю». В лобби модель слышит всех, но реплика стартует только после ~2.5 с тишины комнаты.

Узкий экран (≤1100px) — вертикально прокручиваемая страница: поле, ряд участников, разговор и подвал чата (mic/cam/«Я готов»/compose) должны доскролливаться; `overflow: hidden` на layout/talk только на широком десктопе. На ≤900px ряд участников листается горизонтально, без бокового скролла всей страницы. Проверка: `e2e/mobile-conference.play.ts`, мок `?mock=1&transport=broadcast`. Поле отправки чата закреплено снизу карточки. В пустой видеоплитке написано полное имя, не инициалы. Если партия уже идёт, а пакет у joiner ещё качается или не сверен, на месте табло — «Игра уже началась» с полоской загрузки (процент, скорость, ETA); ряд кнопок с заглушками «Игрок 1…» не рисуется, без данных партии имя — «нет данных». После входа Jitsi перечитывается уже существующий список участников и их дорожек, поэтому поздний joiner видит мастера и игроков; участник «Ведущая» в видеополосе не показывается (камеры у неё нет) — уровень её речи из Jitsi пульсирует золотой рамкой на портрете над «Разговором», той же анимацией, что у говорящих плиток. Если на телефоне ОС оборвала локальный микрофонный `MediaStreamTrack` при включённом мике, клиент сам пересоздаёт и публикует дорожку заново (иначе mute/unmute молчит, рамка не пульсирует, мастер не слышит). Их звук играет через `<audio>`, которые клик входа разблокировал заранее: один Web Audio на телефоне молчит, видеоплитки звук комнаты не играют; частые обновления уровня голоса не перепривязывают `<video>` и не заставляют камеры моргать. Смесь для модели клонирует только удалённые аудиодорожки: тот же трек в `<audio>` и в Web Audio на Chromium глушит миксер. Локальный микрофон мастера в микс идёт без клона и только пока он включён на панели — иначе `mute` не доходил до модели. На выборе и ответе в микс модели попадает только ход текущего игрока (`setModelHearOnly`); чужие `<audio>` продолжают играть. Повторный поток «Ведущей» заменяет дорожку, не копится. Текстовый чат в колонке подписан «Чат · имя»; при выходе и новой комнате он очищается. Приветствие, мостик, уточнение выбора и подсказки про микрофон не продолжают историю лобби (`conversation: none`). Поздний `selectQuestion` / `submitAnswerJudgment` с чужим `turn` отбрасывается и не сбрасывает новый pending tool. Речь ответа привязана к `attemptId` и времени открытия попытки: запоздавший `speech_stopped`/транскрипт прошлой попытки (после `silence` или смены игрока) не уходит в чужой ход. Выбор, ставки и blurt инвалидируются отдельными epoch (`choiceEpoch` / `betEpoch` / `buzzEpoch`); `CHOOSER_OFFLINE` бампит выбор. Автоапелляция «вернуть Маше очки по позднему верному транскрипту» — в to-do, не в коде. «Следующая камера» при ошибке устройства пробует следующую и после удачного `replaceTrack` не dispose живой дорожки. Если в `choosing.listening` микрофон выбирающего непрерывно выключен, ведущая через 3 секунды и дальше каждые 5 секунд (`mutedChooserRepeatMs`) сама придумывает короткую новую фразу, что микрофон не включён, и обращается по имени; выбор при этом не закрывается. Если в `answering.waiting` микрофон отвечающего непрерывно выключен 3 секунды, ведущая один раз за попытку сама придумывает короткую фразу, что микрофон выключен (по имени, тёплый тон), не останавливая таймер ответа; начало ответа обрывает эту подсказку. Joiner раз в две секунды шлёт мастеру ограниченные обезличенные батчи своего trace; мастер добавляет последние записи каждого игрока в «Скопировать дебаг», принимая их только после привязки `clientId`/секрета/endpoint. Аудио `.delta` в консоль не печатаются, Jitsi работает на WARN+. Снимки presence в очереди Bridge Channel идут раньше кусков пакета; окно передачи — до 16 кусков и 512 КиБ сырых байтов; при `bufferedAmount` data channel выше ~256 КиБ новые куски не шлём, пока буфер не спадёт. Повторный `hello` только дозаполняет окно, без нового offer-флода. Joiner считает мастера живым и по снимку, и по `packOffer`/`packChunk` (10 с без любого из них — «Мастер отключился»). В лобби на карточке качающего игрока рядом с процентом видны скорость и ETA (мастер считает по `packAck`, кладёт в `presence` снимка). Ведущая реагирует на смысловые стадии, не на проценты и не на скорость; быстрые вход/сверка/готовность объединяются, между событийными репликами минимум 15 секунд. Если ничего не меняется, раз в 25 секунд нейтрально перечисляет, кого ждём и что у них (можно коротко по ETA), либо подхватывает разговор; «можно начинать» — только когда все гости скачали и готовы. Обычно два коротких предложения, для перечня имён можно три. Повторный `packVerified` уже готового игрока не сбрасывает `ready`.

- Вопросы берутся из `.siq`. На старте дропдаун перечисляет каждый `.siq` в `public/packs` (плагин Vite читает каталог) и пункт «Выбрать свой…» (файл `.siq`, `.zip` или `content.xml`). Свои пакеты идут первыми, с подписями из `src/game/catalog.ts`; чужой файл показывается по имени. Исходники своих пакетов — `packs/*.xml`, сборка `npm run packs`. Чужие пакеты в репозиторий не класть: в `.gitignore` перечислены конкретные имена, каталог целиком и демо-пакеты не игнорируются.
- До «Начать игру» стартовая форма — пакет, имена, модель, ключ и кнопки: без «Скопировать дебаг», без строк связи и микрофона и без индикаторов ожидания сессии. Внизу карточки production показывает строку «Версия YYYY-MM-DD HH:mm:ss хэш-коммита», а в остальных сборках — «Режим разработки». Имена — маленькое поле: с новой строки или через точку с запятой, пустые куски пропускаются. Пока ничего не сохранено, в поле уже «Игрок 1; Игрок 2; Игрок 3;», и та же строка стоит подсказкой. Пустое поле оставляет «Игрок 1», «Игрок 2» и «Игрок 3». Игроков может быть сколько угодно. После нажатия, пока идёт подключение, одна строка: «Открываем микрофон», затем «Подключаемся». Копия дебага остаётся на экране партии.
- Партия пишется в `localStorage` (`aisigame.game`) на каждом ходе, а онлайн-лобби — сразу после его открытия. В снимке поле `version` (`savedGameVersion`, сейчас `1`) — схема формата, не commit сборки: чужой номер `readSavedGame` отбрасывает; поднимать константу только при несовместимом изменении. «Продолжить прошлую игру» сразу поднимает пакет из каталога, а пакет с диска — после повторного выбора файла. В кнопке следующей строкой стоит «Онлайн · Название пакета» или «За столом · имя-файла.siq»; префикса «Прошлая игра:» нет, название обязательно, для старого снимка крайний fallback — `packId`. Имя своего файла и sha256 его байтов лежат в снимке, не в `aisigame.start`; самих байтов и ключа там нет. Клик сразу открывает выбор файла. Чужой файл — `window.alert` с нужным именем и обоими хешами, партия не стартует. Старый снимок без хеша показывает имя, если оно сохранено, и продолжается без проверки. «Выход» стирает сохранение и оставляет кнопку неактивной. Имена и пакет из каталога лежат отдельно в `aisigame.start` и после «Выхода» остаются.
- В конференции мастер кладёт `commit` (`buildCommit()`: в production — хеш коммита, иначе `dev`) в каждый `snapshot` и `packOffer`. Joiner сравнивает со своим: при расхождении или пустом поле у мастера пишет «Версия не совпадает с мастером: у вас …, у мастера …», рвёт комнату (`onFatalError`) и пакет не качает.
- Вопрос с вариантами (`answerOptions`, в пакете пятой версии рядом стоит `answerType` select) показывает на табло букву и текст или картинку каждого варианта. Ведущая читает их вместе с фразой вопроса. Эталон пакета — буква, и тот же ответ засчитывается текстом варианта; вслух, когда ответ уже можно назвать, она говорит букву и этот текст, например «D. Звёздные войны». Остальные варианты она при этом не перечисляет. Комментарий автора из `info` на табло не выходит.
- Цены и темы раунда остаются как в файле. Несколько вопросов одной темы и одного номинала — одна ячейка: выбор открывает следующий несыгранный, ячейка остаётся, пока в стопке есть такой вопрос. Спецвопросы (кот, аукцион, мешок) и вопросы без текста и без медиа пропускаются с предупреждением на старте. В пакете пятой версии аукцион помечен типом `stake` и пропускается так же. После моргания ячейки вопрос крупно занимает табло: туда же картинка, звук и видео. В старых пакетах файл указан как `@имя`, звук — атом `voice`, а в архиве имя часто записано процентами. Кусок после атома `marker` и картинка или ролик из поля ответа — это показ ответа: на табло он появляется вместе с правильным ответом, не вместе с вопросом. Картинка ответа — сразу с эталоном; звук и ролик ответа — после того как ведущая договорила объявление, ещё `answerMediaHoldMs` (4 с), пока `announcing.holding` (если клипа нет, узел пропускается). Картинка вопроса при одном звуке ответа остаётся рядом. У вопроса картинка сразу, звук и ролик — после того как ведущая дочитала текст. У плеера нет кнопок: звук и ролик сами начинают играть и, если короче своего окна, крутятся по кругу. Нажатие кнопки и конец окна кнопки ставят их на паузу и снимают цикл, позиция сохраняется; в перехвате и под объявлением ответа они не продолжаются. Короткий сигнал кнопки остаётся отдельным звуком. На музыкальном вопросе в поле звука виден индикатор уровня, который двигает сам звук; тишина и пауза оставляют его в покое. Звук и ролик вопроса и ответа проходят через мягкий лимитер Web Audio: громкие пики быстро сажает и держит, тихие чуть поднимает makeup-ом, без сильной «качки» динамики; стрелки метра читают сигнал до лимитера. Если текста нет, она говорит «посмотрите» или «послушайте». Файл кладётся в `.siq` рядом с `content.xml`. Пакет «Наглядно» — свой пример с кругом, тремя сигналами и белым квадратом.
- После обычного раунда ведущая коротко называет имя и счёт каждого, затем объявляет следующий раунд или финал и просит выбрать. Темы и цены не перечисляет. Победителя называет в конце партии. В финале выбирают одну тему, ставку называют игроки со счётом больше нуля, от меньшего к большему. Отвечают в том же порядке. Очки меняет ставка, не цена вопроса. Если в финал некого пускать, партия заканчивается.
- Неверный ответ или молчание после кнопки списывает номинал, но ячейку не закрывает. Этот игрок больше не жмёт кнопку на этом вопросе. Неверный ответ (реплику услышали) ведущая коротко и сухо своими словами отмечает как неверный и называет «минус» номинал, без правильного ответа и без приглашения жать кнопку. Если за окно ответа ничего не услышали (тишина / нет распознавания) — это не «неверно»: она свободно, тепло говорит, что ничего не расслышала (можно про микрофон), и всё равно называет «минус» номинал; формулировку выбирает сама. Если ещё есть кому отвечать, кнопки снова открыты 5 секунд (`stealBuzzerMs`). Первое окно после чтения по-прежнему 10 секунд (`buzzerMs`). Если ответ верный, она так же коротко своими словами подтверждает это и называет «плюс» номинал. Правильный ответ при этом не показывает и не произносит. После верного ответа в «Разговоре» под репликой ведущей пишется эталон пакета («Правильный ответ: …»): вслух она его не произносит, на табло его нет, в «Оценке» по-прежнему только статус и что услышано. На табло и вслух он появляется, если никто не ответил, все, кто мог, ответили неверно, или ячейка закрылась потому, что ответ не разобрали, он спорный, его нужно было уточнить, либо оценка не успела за отведённое время. В этом случае она сначала произносит один самый очевидный ответ из пакета: не весь список и без слова «дословно». Второй вариант — только если это другие слова и оба годятся. Свой ответ она не придумывает. Ответ звучит раньше короткой строки, что неверно или что время вышло. За две секунды до конца десятисекундного окна кнопки звучит короткий сигнал в одну секунду (`buzzerBeepMs`), и кнопку ещё можно нажать. Когда окно истекло и ячейка закрылась, она произносит ответ пакета: не говорит, что кнопку не нажали, и не предлагает выбирать следующий. Если на этом вопросе после кнопки уже был неверный ответ, примерно в половине случаев (`closeGuessCoin`, в тестах подменяется) перед эталоном она одной короткой фразой говорит, что попытка была близкой: только когда реплика явно про то же соседним заголовком — часть вместо целого, узкое название той же истории, персонаж вместо произведения, — словами игрока, затем один очевидный ответ пакета. Если монетка молчит, попытка про другое, это созвучие вроде «Читов» при «Титов» или фраза была без кнопки, звучит только ответ пакета. Пока ячейку ещё можно перехватить, близость не упоминает. То же правило, когда ответ называют потому, что ошиблись все или у последнего вышло время. Если за это окно кто-то сказал фразу без кнопки или её перебили, пока она читала, следом одна короткая фраза: ответ называют только после кнопки. Если было тихо, этой лекции нет. Дальше партия сама идёт к выбору, следующему раунду, финалу или концу. В финале кнопок нет: ответ не называют, пока не ответил последний.
- Ответы смысловые, не «да/нет». Очки меняет только XState. Оценка ответа идёт отдельным ходом без истории разговора: в нём только текст ячейки, эталон и расшифровка этой реплики. Если модель вернула чужой questionId или в пояснении процитировала другое произведение, верный статус не принимается. 9 октября на «Времена года» она засчитала «Бетховен» как верный, потому что перед этим сама сказала «Лунную сонату». Пересказ того же смысла, в том числе пояснение загадки вместо цифры, считается верным. Если реплика после обычной нормализации (регистр, ё, знаки, кавычки и пробелы) целиком совпала с одним из эталонов, машина ставит correct, даже когда модель вернула incorrect, needs_clarification или ambiguous. Текст в скобках внутри одного эталона — ещё одна форма целиком, не поиск подстроки. 9 октября на вопросе-коде «Закодированная классика» игрок сказал «Мастер и Маргарита», эталон был тот же, а модель сняла 900. То же слово по слогам («пы ле со сел» при «пылесосел») — тоже correct, не созвучие. Созвучие не верно и не неверно: «Читов» при «Герман Титов», «Твэнсдей» при «Уэнсдэй», «Новоселов» при «Ногу свело». Очки не меняются, ответ не называют, тот же игрок после «Повторите, пожалуйста» отвечает ещё раз, не больше `maxClarifications` (сейчас 1), затем это обычная ошибка. Низкая уверенность распознавания просит повтор только вместе с таким сходством; если поля нет, решает одно созвучие.
- Кнопки игроков: левый Ctrl — первый, пробел — второй, правый Ctrl — третий. Остальные только на экране. Подписи клавиш под первыми тремя. Ряд игроков умещается целиком, сколько имён ни ввели. Пока кнопки открыты, нажатие отдаёт ответ; повтор зажатой клавиши игнорируется. Если на обычном вопросе нажать раньше — пока ячейка моргает или с начала чтения не вышло раннее окно (3–8 с по длине вопроса) — это фальстарт: кнопка вспыхивает красным и гаснет `falseStartMs` (2,5 с). Пока она гаснет, этот игрок нажать не может, чужие кнопки штраф не держит. Когда вспышка прошла, жать можно. Очков фальстарт не меняет. Пауза этот штраф замирает. В финале, при выборе ячейки и в открытом окне фальстарта нет. Если фальстарт на вопросе был и чтение кончилось раньше ранней кнопки, после чтения она примерно в половине случаев коротко называет имена и говорит про фальстарт (тон вроде «Вася, фальстарт»), своими словами, без ответа пакета. Тогда 10 секунд стартуют после этой фразы. Если монетка молчит, часы стартуют сразу, как она дочитала. Если десять секунд уже идут, пока она читает, эта реплика не вставляется и полоска не начинается заново. Монетку можно подменить в тестах.
- Длительности партии лежат в `src/options.ts` обычными константами; раннее окно кнопки на чтении считает `earlyBuzzerMsFor` (3–8 с по длине вопроса и разбросу), подсказка о выключенном микрофоне на ответе — один раз через `mutedAnswerReminderMs` (3 с), а на выборе вопроса первая через те же 3 с и дальше каждые `mutedChooserRepeatMs` (5 с); после объявления эталона звук или ролик ответа держат табло `answerMediaHoldMs` (4 с): позже их заберёт экран настроек.
- Кто выбирает вопрос, лежит в `chooserId`. В начале каждого раунда и на выборе темы финала это игрок 2, если игроков хотя бы двое, иначе первый. После ответа в раунде выбирает последний, чью попытку оценили или кто промолчал после кнопки. Пока табло ждёт ячейку или тему, на его кнопке написано «выбирайте вопрос» и она подсвечена. Имена и счёт остаются. Ведущая может назвать имя, когда просит выбрать вопрос, когда говорит, что верно или неверно, и в строке счёта между раундами.
- Кнопка «Пауза» в шапке глушит микрофон и звук ведущей локально и останавливает таймеры. Ведущая в это время не ждёт. «Дальше» возвращает ту же фазу и снова открывает микрофон в слушающих состояниях, даже если за паузу доиграла только подсказка про микрофон. Пока пауза, можно копировать дебаг и диктовать отчёт в другое окно.
- «Остановить» закрывает сессию и таймеры и оставляет экран партии. Красное состояние «Остановлена» остаётся в коде. Кнопка в шапке сейчас скрыта. «Выход» возвращает в меню и стирает сохранённую партию.
- Если канал событий закрылся или реплику ведущей не удалось отправить, партия не ждёт её фразу и не возвращается к глухому выбору. Экран уходит в меню с ошибкой «связь прервалась». Короткий запасной таймер звука (8 с) срабатывает, только если воспроизведение так и не началось, и снимается, как только звук пошёл: дальше фаза ждёт `stopped`. 9 октября после нераспознанной реплики просьба повторить не ушла, портрет молчал, потом выбор остался глухим и выглядел как «Ведущая думает». 10 октября после таймаута оценки (`judgeMs`) поздний `response.done` с `submitAnswerJudgment` обнулял текущую речь в `RealtimeClient`: `stopped` объявления ответа пакета уже не вызывал `finishSpeech`, машина оставалась в `announcing` со статусом «Оценка не пришла вовремя». Клиент больше не трогает `speech` на tool done — только `pendingTool` и колбэк; чужой `turn` не сбрасывает новый pending и контроллером не принимается.
- В шапке партии над названием строка статуса: пакет, раунд и название выбранной модели. Название с треугольником выглядит как текст; список открывается по нажатию. Смена модели там сохраняет её и перезагружает страницу, снимок партии остаётся. Сумма токенов из каждого `response.done`: до тысячи как есть, дальше `1.5K` и `1.2M`. Цену в долларах не показываем. Транскрипция в эту сумму не входит. Счётчик обнуляется в начале новой сессии.
- В шапке партии связь, микрофон и звук ведущей — чёрно-белые значки без подписей: слова только в подсказке, а если связи нет, значок связи красный и мигает.
- «Скопировать дебаг» после успешного копирования на две секунды меняется на «Скопировано ~N КБ/МБ». UTF-8-размер относится ко всей фактически скопированной строке, включая удалённые логи игроков. Скрытая резервная подпись держит ширину кнопки неизменной.
- Портрет ведущей стоит над колонкой «Разговор». Крупная подпись и одна-две мелкие строки фазы живут внутри карточки, отдельной строки под ней нет. За столом на выборе ячейки мелкая строка — «назовите тему и стоимость», а на теме финала — «Выберите тему финала». В конференции персональный ход вместо общего «Не говорите» подписан полным именем: «Вася выбирает вопрос», «Вася выбирает тему финала», «Вася отвечает» или «Вася делает ставку»; одинаково для владельца хода и наблюдателей. Одинаковый смысл не повторяется: «Ведущая думает» уступает «Ведущая оценивает ответ», «Сейчас говорит ведущая» уступает «Ведущая читает вопрос». Колонка шире технической. Зелёная пульсация и «Можно говорить» — рука у уха, она слушает выбор ячейки или ответ. Пока она говорит, рот открыт и волны у рта, без ладони «стоп» и без руки у уха. «Жмите кнопку» — она слышит комнату, но ответ без кнопки не засчитывается. После ранней кнопки портрет уже «Жмите кнопку», даже если голос чтения ещё идёт. Речь без кнопки не останавливает и не продлевает ни 10 секунд, ни 5 секунд на перехват: полоска доходит до конца. Кашель и короткий шум ничего не делают. Напоминание про кнопку звучит только после ответа, когда окно кнопки истекло и ячейка закрылась, и только если за окно уже была фраза без кнопки или её перебили во время чтения: эталон пакета остаётся обязательным, а короткая пометка про кнопку — своими словами. Что кнопку не нажали, она при этом не говорит. Речь во время чтения её не останавливает и ответом не считается. Посреди 10 и 5 секунд отдельного «нажмите кнопку» нет, и эти часы от речи без кнопки не замирают. Пока её звук идёт, портрет остаётся говорящим, даже если фаза уже сменилась.
- Тон ведущей тёплый и чуть кокетливый. В приветствии и в похвале уместен один короткий звук смеха, вроде «хи-хи», а не слова «с лёгким смешком» или «хихикаем» и не ремарка в скобках. Ошибку она по-прежнему отмечает сухо, без этого звука. Дословное чтение вопроса и тела ответа пакета не разбавляет и пометку тона вслух не включает. Свободные реплики (приветствие, мостик, уточнение выбора, верно/неверно без эталона, фальстарт, ставки, ход финала, лобби, `CHOOSER_OFFLINE`, напоминание микрофона выбирающему и отвечающему, хвост про кнопку после эталона) идут как ситуация + цель + ограничения: формулировку модель выбирает сама, без списка «скажи ровно эту фразу / один синоним». Жёсткими остаются чтение вопроса и эталон пакета, когда правила требуют назвать ответ.
- Под вопросом время — полоска у нижнего края карточки: она убывает от полной до пустой, без числа секунд.
- Вопрос в чат пишется из пакета, когда ведущая начинает его читать. Перед этим выбранная ячейка трижды моргает ярче, около 1,1 с (`cellFlashMs`), и текста вопроса на табло ещё нет. Сообщение хода чтения — только фраза пакета. Инструкция этого хода не велит «сказать вслух» и не велит «повторить фразу»: ведущая начинает с этой фразы, без темы и номинала. Чтение идёт отдельным ходом без истории разговора. Если ведущая говорит другое, аудио сбрасывается. Один повтор, затем ту же фразу произносит сам браузер, и партия не продолжается на чужом вопросе. На обычном вопросе после раннего окна (`earlyBuzzerMsFor`, 3–8 с по длине вопроса) с начала чтения (`reading.armed`) кнопки, статус «Жмите свою кнопку» и полоска десяти секунд уже живые, даже если она ещё читает: нажатие обрывает её звук и открывает ответ. Когда она дочитала, остаток полоски не обнуляется. Если она дочитала раньше этой задержки, десять секунд стартуют тогда. Если окно вышло, пока она ещё читает, чтение обрывается. Жёсткие 30 с звука не открывают эту кнопку впервые. Речь без кнопки во время чтения не отменяет её звук; если сервер всё же сбросил или обрезал эту фразу, полоска стартует сразу, а сброс предыдущей реплики не стирает уже начатое чтение. В финале во время чтения кнопки закрыты.
- Пока она ждёт выбор ячейки, распознаванию передаётся список открытых тем и номиналов. К выбору привязывается только расшифровка этой реплики, не предыдущей. Расшифровка, которая совпадает с этой подсказкой, начинается с «Тема и цена:» или длинным куском повторяет открытый каталог, не пишется репликой игрока и ячейку не выбирает: в технической колонке одна короткая заметка, микрофон остаётся в выборе. После кнопки, в `answering.waiting` и `answering.hearing`, и на повторе после «Повторите», распознаванию передаются принятые ответы этой ячейки, без текста вопроса и без тем. До кнопки этих ответов в подсказке нет. Расшифровка, которая повторяет эту подсказку целиком или обёртку со списком, не пишется репликой и не оценивается: заметка, счёт тот же, микрофон снова слушает. Само слово эталона идёт в оценку. В «Оценке» строка «Услышала» — текст распознавателя, не пересказ модели. Тема с точками вроде «П......Ц» локально совпадает с аббревиатурой или словом с теми же первой и последней буквами, если такая открытая тема одна. Пока она просит повторить ячейку, микрофон открыт: если игрок заговорил, её фраза обрывается и слушается новая.
- Справа колонка разговора: реплики ведущей, транскрипт игрока и оценка. В оценке только статус и что услышано. Эталон и пояснение модели туда не пишутся: в пояснении она называет правильный ответ, а ячейка после ошибки ещё открыта. Пояснение остаётся в контексте машины и в копии дебага. Реплика ведущей — обычный абзац на всю ширину колонки, не сетка портрета. Технические события на экран не выходят. Важные события пишутся в консоль браузера с префиксом `[aisigame]`; покадровые `.delta` не сохраняются и не печатаются, чтобы не забивать буфер и не тормозить DevTools. Кнопка «Скопировать дебаг» в шапке, с гаечным ключом, кладёт в буфер обмен состояние машины и контекст. Скопированный дебаг должен сохранять связь, смены сессии, статус и текущее состояние машины: по этим дампам чинят баги. Ключ в этот лог не попадает. В конце копии стоят адрес страницы (`location.origin`) и короткий хеш коммита сборки; если git при сборке недоступен, вместо хеша пишется `dev`. Полосы прокрутки у вопроса, поля и обеих колонок скрыты.
- Если ведущая объявляет неверный факт, в объявлении ей передаётся дословный эталон из вопроса. Свой ответ она придумывать не должна. Наблюдение 9 октября: на «ближайшую звезду» эталон был «Солнце», игрок сказал «Бетельгейзе», ведущая вслух назвала «Сириус», потому что в реплике об ошибке эталона не было.
- Реплика игрока пишется в колонку разговора как «Услышано», в том числе «речь не распознана». Кашель и короткий шум не открывают ячейку. Выбор темы идёт по распознанному тексту: без ясных темы и номинала ячейка не берётся.
- Справа одна колонка «Разговор»: крупные реплики. Новая строка докручивает её до низа.
- Кнопки шапки со значками: пауза, дальше, выход, скопировать дебаг, пропустить раунд. «Остановить» в шапке сейчас скрыта. «Пропустить раунд» заканчивает текущий раунд с тем же счётом: несыгранные ячейки не доигрываются, ведущая объявляет следующий раунд, финал или конец партии.
- Первое приветствие чуть быстрее (`welcomeSpeechSpeed` 1.25): коротко здоровается и зовёт выбрать вопрос. Темы и номиналы не называет: они на табло. Дальше темп обычный. Мостик к финалу может сказать «выберите одну тему», без списка названий.
- Ведущая не произносит ремарку про темы и цены, а шесть и больше тем текущего раунда целиком помещаются на табло над игроками.

Backend не добавлять, пока прямой вызов из браузера сам не откажется. Ключ не писать в код, `.env`, логи, тесты и README.

## Запуск

```bash
npm install
npm run packs
npm run dev
npm test
npx playwright install chromium
npm run look
```

`npm run look` гоняет Playwright. `http://127.0.0.1:5173/?mock=1` по-прежнему сразу поднимает заглушку без ключа. В списке моделей тот же мок называется «Мок для тестов»: `e2e/match.play.ts` выбирает его на обычном адресе и проходит демо-пакет. Живой голос — с ключом выбранной модели, без мока.

Dev-сервер слушает сеть на порту 5173, чтобы открыть его с планшета.

Живой сайт: https://roginvs.github.io/aisigame/. Продакшен-сборка ставит Vite `base` `/aisigame/`, чтобы пакеты и портрет открывались с адреса проекта. `npm run dev` и `npm run look` остаются на `/`. Pull request и push в `master` проверяет `.github/workflows/ci.yml` (`npm ci`, `npm test`, `npx tsc -b`). Push в `master` ещё собирает сайт в `.github/workflows/pages.yml`: те же проверки, затем `npm run build`, и публикует Pages.

## Куда класть код

- `src/game/machine.ts` — правила, таймеры, счёт, раунды и финал.
- `src/game/earlyBuzzer.ts` — длительность раннего окна кнопки по длине вопроса.
- `src/game/savedGame.ts` — снимок партии в `localStorage` (`aisigame.game`), без ключа API.
- `src/game/siq.ts` — разбор `.siq` / `content.xml`.
- `src/game/pack.ts` — поиск вопроса в текущем раунде.
- `src/game/controller.ts` — связка машины и голоса. Контроллер говорит только с `GameVoice`.
- `src/realtime/voice.ts` — `createVoice`: мок, OpenAI, Grok или Gemini.
- `src/realtime/models.ts` — список моделей и ключи `localStorage`.
- `src/realtime/client.ts` — WebRTC OpenAI и приём провода `VoiceWire`, без React.
- `src/realtime/grokWire.ts` и `src/realtime/geminiWire.ts` — сокеты xAI и Google в события OpenAI.
- `src/realtime/mockClient.ts` — заглушка «Мок для тестов» и для `?mock=1`, без ключа и без сети.
- `src/ui` — только отображение и клики.
- `src/conference/packProgress.ts` — скорость и ETA загрузки пакета по `packAck` (мастер → `presence`).
- `src/options.ts` — длительности партии.
- `src/config.ts` — модель, голос и адрес API.

React не хранит игровые правила. Модель не меняет счёт сама: только function calling, аргументы проверяет машина.
