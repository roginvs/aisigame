# AGENTS.md — правила работы агента

Браузерная викторина «Своя игра» с голосовой AI-ведущей. Стек: React + TypeScript + Vite + XState 5; партии из пакетов `.siq`; голос — Realtime API (OpenAI/xAI/Google/Qwen/мок); онлайн через Jitsi; локальный режим «за столом». Репозиторий: https://github.com/roginvs/aisigame, сайт: https://roginvs.github.io/aisigame/.

## Обязательные правила

1. **Конкретная задача — не аудит репозитория.** По просьбе «исправить X» правь только X: без общего осмотра кода, чтения всех документов и реорганизации несвязанных мест. Полная сверка проекта и документации — только по явной просьбе.
2. **Читать только нужное.** Открой профильный документ задачи (карта ниже) — и в нём только затронутый раздел по оглавлению вверху файла или Grep-ом по заголовку. Большие документы и архив целиком не загружай.
3. **Обновлять точечно.** После задачи обнови затронутый раздел профильного документа и свой пункт `to-do.md`. Датированные решения («N октября …») пиши в профильный документ задачи, не сюда; AGENTS.md меняется, только когда изменились правила, карта, команды или термины. Этот файл не вести как журнал.
4. **Термины ровно эти:** **контроллер** — машина состояний на устройстве мастера (`src/game/machine.ts` + `controller.ts`), держит главное состояние, модель, микшер и дорожки, людям ничего не показывает; **мастер** — игрок за тем же компьютером (экран из полученного состояния + свои кнопки управления); **игрок** — любой участник, кроме мастера. **Главное состояние** — только оно управляет логикой; **полученное** — только отображение, строится из снимка одним путём у всех (игроки — из транспорта, мастер — петля `LoopbackStateReceiver`). Действия мастера идут прямо в контроллер, игроков — сообщениями Jitsi; те и другие — одни события контроллера. Не называть контроллер «мастером». Подробнее — «Термины» в [docs/ONLINE.md](docs/ONLINE.md).
5. **Модель не правит счёт.** Очки меняет только XState; модель меняет счёт только через function calling, аргументы проверяет машина. React не хранит правила: `src/ui` — только отображение и клики. Куда класть код — карта ниже и «Куда класть код» в архиве.
6. **Границы связи.** Backend не добавлять, пока прямой вызов из браузера сам не откажется. Ключ API не писать в код, `.env`, логи, тесты и README.
7. **Качество.** Типы строгие (`strict`, `noUncheckedIndexedAccess`), eslint запрещает `any` и `[object Object]` в шаблонных строках; глушить правила директивами нельзя — чини тип. Перед отчётом: `npm test` (включает lint) и `npx tsc -b`; экраны/графика — e2e `npm run look`.

## Инварианты партии

Автор принял 24 октября 2026. Это жёсткие правила. Почему так — [STABILITY.md](docs/STABILITY.md), раздел «А». `docs/PROMPTS.md` для дословного текста не заменять.

1. Счёт меняет только машина. Контроллер не пишет `players[].score`.
2. У хода один ключ: вопрос, игрок, `attemptId`, `itemId` реплики, id ответа модели. Событие с чужим ключом — пустое, без побочных сбросов.
3. Позднее событие закрытого хода не начинает новый ход и не отменяет уже заказанную речь другого id.
4. Чтение вопроса принято, только если по порядку дозвучало последнее содержательное слово. Иначе повтор, а не «как будто прочитано».
5. Эталон не входит в историю свободной речи. Ход судьи и ход чтения не оставляют его в сессии провайдера, у которого нет `conversation: none`.
6. Один владелец таймера окна. Пауза этого окна следует правилу автора (сейчас у машины — полная длительность).
7. Фильтр речи в коде только против эха нашего же текста. Смысл «шум / не выбор / неверно» решает модель или явный эталон, не новый список слов.
8. Одна дорожка — один потребитель. Звук ведущей в комнату и в ухо мастера не делится вторым графом. На Android элемент пересоздаётся после микрофона.
9. Провайдер, который не умеет пункт, не притворяется, что умеет: отличие записано в проводе и в тесте провода, а не починкой контроллера под один дамп.
10. Каждый исправленный баг событий модели сопровождается сценарием в `src/realtime/replay.test.ts`.
11. Речь до нажатия кнопки не оценивается и счёт не меняет. В попытку идёт реплика, начатая после нажатия. Провод без разреза буфера этому не противоречит: контроллер не считает до-кнопочный item ответом.
12. Новый item и старт речи после кнопки не делают текст ответом, если этот текст равен последней фразе, уже закрытой до кнопки, или только продолжает её. В оценку идёт хвост; префикс пишется в чат как «до кнопки». Пустой хвост — не ответ.
13. СМЫСЛ ОТВЕТА РЕШАЕТ МОДЕЛЬ ПО ПОЛНОМУ ТЕКСТУ РЕПЛИКИ. Код не чистит паразиты, мат, повторы и словоформы списками слов и не подменяет из-за них вердикт модели. Локально засчитать можно только точное совпадение с эталоном. Проверка префикса (пункт 12) отрезает только фразу, уже закрытую до кнопки, и не выбрасывает хвост, в котором ответ.

## Как работать с автором

- Числа и настройки не выдумывать: называть текущее значение, откуда оно и почему.
- Открытые вопросы — нумерованным списком. В чате параллельно идут несколько обсуждений: держать все открытые вопросы, переносить их в следующие ответы и явно закрывать («вопрос 3 решён»). Понятное делать сразу, неясное переспрашивать с новыми номерами.
- Объяснять просто и подробно, с конкретными примерами и ссылками `файл:строка`.
- Debug-логи читать с конца.
- Параллельные агенты можно запускать в отдельных git worktree, у каждого свой `AISIGAME_TEST_PORT`; перед push — `git pull --rebase`.
- Проверку на телефоне/планшете/десктопе вести видимо, на экране бота, перед началом — звуковой сигнал ~3 с.

## Принципы кода

1. Естественный язык разбирает только LLM: никаких regex и списков слов по тексту, никаких дополнительных перепроверок с задержкой. В коде остаётся только отсев эха ведущей.
2. Реплики ведущей не хардкодить: модель получает ситуацию и что донести, слова выбирает сама. Дословно — только текст вопроса и технические системные строки. Шутить иногда можно ([GAME](docs/GAME.md#молчание-игрока-14-октября-2026), «Шутки ведущей»).
3. Звук ведущей и команды модели запускает машина состояний на смене состояния, не экран. Новый снимок или перерисовка не обрывает и не перезапускает речь; события экрана (кончилось видео ответа) идут в контроллер событиями.
4. Мастер и игроки устроены одинаково: мастер рисует из того же снимка, что рассылает (правило 4 выше).
5. Мастер только маршрутизирует звук: ведущая идёт в конференцию, его микрофон попадает в модель через конференцию/микшер, как у всех; все звуки игры — через конференцию.
6. Обратной совместимости нет: версия сверяется по commit, мастер на новом коммите выкидывает игроков.
7. Только id (Jitsi id / clientId), имена — только для обращения, одинаковые имена допустимы. В данных — id, имя каждый экран берёт из снимка.
8. Тексты на экране и в чате гендерно-нейтральные.
9. В debug-лог каждый участник пишет вход, commit, размер экрана/окна, DPR, zoom и ориентацию. Лог игрока чистится только при входе в другую игру или когда он становится мастером.

## Эффективная работа AI-агента и экономия контекста

Дополнение к правилам 1–3: качество работы важнее экономии, она не должна снижать качество исправлений, нарушать требования проекта или пропускать нужные проверки.

- Архивы, исторические отчёты и старые изменения не читать без прямой необходимости: история выполненных задач — не рабочий контекст.
- Работая над задачей из `to-do.md`, не изучай весь список — только её пункт.
- Не перечитывать уже изученные файлы без причины; искать по конкретным функциям, строкам и заголовкам.
- Обновлять только задетую документацию, без длинных исторических отчётов о каждой правке.
- Не дублировать технические решения в разных документах — в остальных местах ссылка на основной источник требований.
- Не затягивать предварительный анализ: когда информации достаточно — правь и проверяй результат.
- Большие задачи делить на небольшие законченные этапы, сохраняя промежуточные результаты.

## Команды

```bash
npm install
npm run packs     # демо-пакет: packs/demo.xml → public/packs/builtin/demo.siq
npm run dev       # 127.0.0.1:5173, слушает сеть (планшет); ?mock=1 — мок без ключа
npm test          # lint + unit-тесты
npx tsc -b
npm run look      # Playwright e2e; порт — AISIGAME_TEST_PORT
npm run build     # production, base /aisigame/ (для Pages)
```

Push в `master` гоняет CI (`.github/workflows/ci.yml`: `npm ci`, `npm test`, `npx tsc -b`) и публикует сайт (`.github/workflows/pages.yml`).
