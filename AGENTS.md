# Инструкции для агентов

Этот файл — короткая рабочая память проекта. Его нужно обновлять при каждой существенной правке: что сделано, что решили, как запускать, какие ограничения ещё действуют.

Полный контекст лежит в `docs/CONTEXT.md`: исходное техническое задание, исследование API, договорённости из обсуждения и текущий статус. Схема партии, как она идёт сейчас, лежит в `docs/GAME.md`. Отложенные задачи — в [to-do.md](to-do.md). Перед работой прочитай их и этот файл. После работы обнови их, если изменились решения, объём прототипа или известные проблемы.

`docs/CONTEXT.md` тоже нужно обновлять постоянно. Не оставляй важные договорённости только в чате.

Игра — этот репозиторий. Каталог раньше лежал в `playground/aisigame` и скопирован сюда без истории того git. Канонический remote: https://github.com/roginvs/aisigame. Локальный путь: `~/aisigame`.

## Сейчас

Прототип уже запускается: связь, машина, пакет вопросов, несколько раундов и финал.

- React + TypeScript + Vite + XState 5.
- Обычный OpenAI API key вводится в браузере и хранится в `localStorage` (`aisigame.openaiApiKey`).
- Прямой WebRTC к `POST https://api.openai.com/v1/realtime/calls` без своего backend.
- Модель `gpt-realtime-2.1-mini`, голос `marin`.
- Вопросы берутся из `.siq`. На старте дропдаун перечисляет каждый `.siq` в `public/packs` (плагин Vite читает каталог) и пункт «Выбрать свой…» (файл `.siq`, `.zip` или `content.xml`). Свои пакеты идут первыми, с подписями из `src/game/catalog.ts`; чужой файл показывается по имени. Исходники своих пакетов — `packs/*.xml`, сборка `npm run packs`. Чужие пакеты в репозиторий не класть: в `.gitignore` перечислены конкретные имена, каталог целиком и демо-пакеты не игнорируются.
- До «Начать игру» стартовая форма — пакет, имена, ключ и кнопки: без «Скопировать дебаг», без строк связи и микрофона и без индикаторов ожидания сессии. Имена — маленькое поле, одно в строке; пустые строки пропускаются. Пустое поле оставляет «Игрок 1», «Игрок 2» и «Игрок 3». Игроков может быть сколько угодно. После нажатия, пока идёт подключение, одна строка: «Открываем микрофон», затем «Подключаемся». Копия дебага остаётся на экране партии.
- Партия пишется в `localStorage` (`aisigame.game`) на каждом ходе: «Продолжить прошлую игру» сразу поднимает пакет из каталога, а пакет с диска — после повторного выбора файла; «Выход» стирает сохранение и оставляет кнопку неактивной. Имена и пакет из каталога лежат отдельно в `aisigame.start` и после «Выхода» остаются; свой файл и ключ туда не пишутся.
- Вопрос с вариантами (`answerOptions`, в пакете пятой версии рядом стоит `answerType` select) показывает на табло букву и текст или картинку каждого варианта. Ведущая читает их вместе с фразой вопроса. Эталон пакета — буква, и тот же ответ засчитывается текстом варианта; вслух, когда ответ уже можно назвать, она говорит букву и этот текст, например «D. Звёздные войны». Остальные варианты она при этом не перечисляет. Комментарий автора из `info` на табло не выходит.
- Цены и темы раунда остаются как в файле. Спецвопросы (кот, аукцион, мешок) и вопросы без текста и без медиа пропускаются с предупреждением на старте. В пакете пятой версии аукцион помечен типом `stake` и пропускается так же. После моргания ячейки вопрос крупно занимает табло: туда же картинка, звук и видео. В старых пакетах файл указан как `@имя`, звук — атом `voice`, а в архиве имя часто записано процентами. Кусок после атома `marker` и картинка или ролик из поля ответа — это показ ответа: на табло он появляется вместе с правильным ответом, не вместе с вопросом. Картинка сразу, звук и ролик — после того как ведущая дочитала текст. Если текста нет, она говорит «посмотрите» или «послушайте». Файл кладётся в `.siq` рядом с `content.xml`. Пакет «Наглядно» — свой пример с кругом, тремя сигналами и белым квадратом.
- После обычного раунда ведущая коротко называет имя и счёт каждого, затем объявляет следующий раунд или финал и просит выбрать. Темы и цены не перечисляет. Победителя называет в конце партии. В финале выбирают одну тему, ставку называют игроки со счётом больше нуля, от меньшего к большему. Отвечают в том же порядке. Очки меняет ставка, не цена вопроса. Если в финал некого пускать, партия заканчивается.
- Неверный ответ или молчание после кнопки списывает номинал, но ячейку не закрывает. Этот игрок больше не жмёт кнопку на этом вопросе. Ведущая коротко и сухо говорит «неверно» или синоним и «минус» номинал, без правильного ответа и без приглашения жать кнопку. Если ещё есть кому отвечать, кнопки снова открыты 5 секунд (`stealBuzzerMs`). Первое окно после чтения по-прежнему 10 секунд (`buzzerMs`). Если ответ верный, она так же коротко говорит «верно» и «плюс» номинал. Правильный ответ при этом не показывает и не произносит. После верного ответа в «Разговоре» под репликой ведущей пишется эталон пакета («Правильный ответ: …»): вслух она его не произносит, на табло его нет, в «Оценке» по-прежнему только статус и что услышано. На табло и вслух он появляется только если никто не ответил или все, кто мог, ответили неверно. В этом случае она сначала произносит один самый очевидный ответ из пакета: не весь список и без слова «дословно». Второй вариант — только если это другие слова и оба годятся. Свой ответ она не придумывает. Ответ звучит раньше короткой строки, что неверно или что время вышло. За две секунды до конца десятисекундного окна кнопки звучит короткий сигнал в одну секунду (`buzzerBeepMs`), и кнопку ещё можно нажать. Когда окно истекло и ячейка закрылась, она произносит ответ пакета: не говорит, что кнопку не нажали, и не предлагает выбирать следующий. Если на этом вопросе после кнопки уже был неверный ответ, примерно в половине случаев (`closeGuessCoin`, в тестах подменяется) перед эталоном она одной короткой фразой говорит, что попытка была близкой: только когда реплика явно про то же соседним заголовком — часть вместо целого, узкое название той же истории, персонаж вместо произведения, — словами игрока, затем один очевидный ответ пакета. Если монетка молчит, попытка про другое, это созвучие вроде «Читов» при «Титов» или фраза была без кнопки, звучит только ответ пакета. Пока ячейку ещё можно перехватить, близость не упоминает. То же правило, когда ответ называют потому, что ошиблись все или у последнего вышло время. Если за это окно кто-то сказал фразу без кнопки или её перебили, пока она читала, следом одна короткая фраза: ответ называют только после кнопки. Если было тихо, этой лекции нет. Дальше партия сама идёт к выбору, следующему раунду, финалу или концу. В финале кнопок нет: ответ не называют, пока не ответил последний.
- Ответы смысловые, не «да/нет». Очки меняет только XState. Оценка ответа идёт отдельным ходом без истории разговора: в нём только текст ячейки, эталон и расшифровка этой реплики. Если модель вернула чужой questionId или в пояснении процитировала другое произведение, верный статус не принимается. 9 октября на «Времена года» она засчитала «Бетховен» как верный, потому что перед этим сама сказала «Лунную сонату». Пересказ того же смысла, в том числе пояснение загадки вместо цифры, считается верным. Если реплика после обычной нормализации (регистр, ё, знаки, кавычки и пробелы) целиком совпала с одним из эталонов, машина ставит correct, даже когда модель вернула incorrect, needs_clarification или ambiguous. Текст в скобках внутри одного эталона — ещё одна форма целиком, не поиск подстроки. 9 октября на вопросе-коде «Закодированная классика» игрок сказал «Мастер и Маргарита», эталон был тот же, а модель сняла 900. То же слово по слогам («пы ле со сел» при «пылесосел») — тоже correct, не созвучие. Созвучие не верно и не неверно: «Читов» при «Герман Титов», «Твэнсдей» при «Уэнсдэй», «Новоселов» при «Ногу свело». Очки не меняются, ответ не называют, тот же игрок после «Повторите, пожалуйста» отвечает ещё раз, не больше `maxClarifications` (сейчас 1), затем это обычная ошибка. Низкая уверенность распознавания просит повтор только вместе с таким сходством; если поля нет, решает одно созвучие.
- Кнопки игроков: левый Ctrl — первый, пробел — второй, правый Ctrl — третий. Остальные только на экране. Подписи клавиш под первыми тремя. Ряд игроков умещается целиком, сколько имён ни ввели. Пока кнопки открыты, нажатие отдаёт ответ; повтор зажатой клавиши игнорируется. Если на обычном вопросе нажать раньше — пока ячейка моргает или с начала чтения не прошло `earlyBuzzerMs` — это фальстарт: кнопка вспыхивает красным и гаснет `falseStartMs` (2,5 с). Пока она гаснет, этот игрок нажать не может, чужие кнопки штраф не держит. Когда вспышка прошла, жать можно. Очков фальстарт не меняет. Пауза этот штраф замирает. В финале, при выборе ячейки и в открытом окне фальстарта нет. Если фальстарт на вопросе был, после чтения она примерно в половине случаев коротко называет имена («Вася, фальшстарт» или «Ого, Маша и Вася, фальшстарт»), без ответа пакета. Тогда 10 секунд стартуют после этой фразы. Если монетка молчит, часы стартуют сразу, как она дочитала. Монетку можно подменить в тестах.
- Длительности партии лежат в `src/options.ts` обычными константами: позже их заберёт экран настроек.
- Кто выбирает вопрос, лежит в `chooserId`. В начале каждого раунда и на выборе темы финала это игрок 2, если игроков хотя бы двое, иначе первый. После ответа в раунде выбирает последний, чью попытку оценили или кто промолчал после кнопки. Пока табло ждёт ячейку или тему, на его кнопке написано «выбирайте вопрос» и она подсвечена. Имена и счёт остаются. Ведущая может назвать имя, когда просит выбрать вопрос, когда говорит, что верно или неверно, и в строке счёта между раундами.
- Кнопка «Пауза» в шапке глушит микрофон и звук ведущей локально и останавливает таймеры. Ведущая в это время не ждёт. «Дальше» возвращает ту же фазу. Пока пауза, можно копировать дебаг и диктовать отчёт в другое окно.
- «Остановить» закрывает сессию и таймеры и оставляет экран партии. Красное состояние «Остановлена» остаётся в коде. Кнопка в шапке сейчас скрыта. «Выход» возвращает в меню и стирает сохранённую партию.
- Если канал событий закрылся или реплику ведущей не удалось отправить, партия не ждёт её фразу и не возвращается к глухому выбору. Экран уходит в меню с ошибкой «связь прервалась». Короткий запасной таймер звука (8 с) срабатывает, только если воспроизведение так и не началось, и снимается, как только звук пошёл: дальше фаза ждёт `stopped`. 9 октября после нераспознанной реплики просьба повторить не ушла, портрет молчал, потом выбор остался глухим и выглядел как «Ведущая думает».
- В шапке партии сумма токенов из каждого `response.done`: до тысячи как есть, дальше `1.5K` и `1.2M`. Цену в долларах не показываем. Транскрипция в эту сумму не входит. Счётчик обнуляется в начале новой сессии.
- В шапке партии связь, микрофон и звук ведущей — чёрно-белые значки без подписей: слова только в подсказке, а если связи нет, значок связи красный и мигает.
- Портрет ведущей стоит над колонкой «Разговор». Крупная подпись и одна-две мелкие строки фазы живут внутри карточки, отдельной строки под ней нет. На выборе ячейки мелкая строка — «назовите тему и стоимость», без номера раунда и без номера игрока перед ней. На теме финала — «Выберите тему финала». Одинаковый смысл не повторяется: «Ведущая думает» уступает «Ведущая оценивает ответ», «Сейчас говорит ведущая» уступает «Ведущая читает вопрос». Колонка шире технической. Зелёная пульсация и «Можно говорить» — рука у уха, она слушает выбор ячейки или ответ. Пока она говорит, рот открыт и волны у рта, без ладони «стоп» и без руки у уха. «Жмите кнопку» — она слышит комнату, но ответ без кнопки не засчитывается. Речь без кнопки не останавливает и не продлевает ни 10 секунд, ни 5 секунд на перехват: полоска доходит до конца. Кашель и короткий шум ничего не делают. Напоминание про кнопку звучит только после ответа, когда окно кнопки истекло и ячейка закрылась, и только если за окно уже была фраза без кнопки или её перебили во время чтения. Что кнопку не нажали, она при этом не говорит. Речь во время чтения её не останавливает и ответом не считается. Посреди 10 и 5 секунд отдельного «нажмите кнопку» нет, и эти часы от речи без кнопки не замирают. Пока её звук идёт, портрет остаётся говорящим, даже если фаза уже сменилась.
- Тон ведущей тёплый и чуть кокетливый: короткий смешок уместен в приветствии и в похвале. Ошибку она по-прежнему отмечает сухо. Дословное чтение вопроса не разбавляет.
- Под вопросом время — полоска у нижнего края карточки: она убывает от полной до пустой, без числа секунд.
- Вопрос в чат пишется из пакета, когда ведущая начинает его читать. Перед этим выбранная ячейка трижды моргает ярче, около 1,1 с (`cellFlashMs`), и текста вопроса на табло ещё нет. В инструкции чтения ей запрещено объявлять тему и номинал: сразу фраза из пакета. Чтение идёт отдельным ходом без истории разговора. Если ведущая говорит другое, аудио сбрасывается. Один повтор, затем ту же фразу произносит сам браузер, и партия не продолжается на чужом вопросе. На обычном вопросе после `earlyBuzzerMs` с начала чтения (`reading.armed`) кнопки уже живые: нажатие обрывает её звук и открывает ответ, а 10 секунд и полоска стартуют только когда она дочитала. Речь без кнопки во время чтения не отменяет её звук; если сервер всё же сбросил или обрезал эту фразу, полоска стартует сразу, а сброс предыдущей реплики не стирает уже начатое чтение. В финале во время чтения кнопки закрыты.
- Пока она ждёт выбор ячейки, распознаванию передаётся список открытых тем и номиналов. К выбору привязывается только расшифровка этой реплики, не предыдущей. Расшифровка, которая совпадает с этой подсказкой, начинается с «Тема и цена:» или длинным куском повторяет открытый каталог, не пишется репликой игрока и ячейку не выбирает: в технической колонке одна короткая заметка, микрофон остаётся в выборе. После кнопки, в `answering.waiting` и `answering.hearing`, и на повторе после «Повторите», распознаванию передаются принятые ответы этой ячейки, без текста вопроса и без тем. До кнопки этих ответов в подсказке нет. Расшифровка, которая повторяет эту подсказку целиком или обёртку со списком, не пишется репликой и не оценивается: заметка, счёт тот же, микрофон снова слушает. Само слово эталона идёт в оценку. В «Оценке» строка «Услышала» — текст распознавателя, не пересказ модели. Тема с точками вроде «П......Ц» локально совпадает с аббревиатурой или словом с теми же первой и последней буквами, если такая открытая тема одна. Пока она просит повторить ячейку, микрофон открыт: если игрок заговорил, её фраза обрывается и слушается новая.
- Справа колонка разговора: реплики ведущей, транскрипт игрока и оценка. В оценке только статус и что услышано. Эталон и пояснение модели туда не пишутся: в пояснении она называет правильный ответ, а ячейка после ошибки ещё открыта. Пояснение остаётся в контексте машины и в копии дебага. Реплика ведущей — обычный абзац на всю ширину колонки, не сетка портрета. Технические события там же, мелким шрифтом. Время события на экране не пишется: оно во всплывающей подсказке при наведении. То же пишется в консоль с префиксом `[aisigame]`. Кнопка «Скопировать дебаг» кладёт в буфер обмен, состояние машины и контекст. Скопированный дебаг должен сохранять связь, смены сессии, статус и текущее состояние машины: по этим дампам чинят баги. Ключ в этот лог не попадает. Покадровые `.delta` не пишем, чтобы лог не забивался. Полосы прокрутки у вопроса, поля и обеих колонок скрыты.
- Если ведущая объявляет неверный факт, в объявлении ей передаётся дословный эталон из вопроса. Свой ответ она придумывать не должна. Наблюдение 9 октября: на «ближайшую звезду» эталон был «Солнце», игрок сказал «Бетельгейзе», ведущая вслух назвала «Сириус», потому что в реплике об ошибке эталона не было.
- Реплика игрока пишется в колонку разговора как «Услышано», в том числе «речь не распознана». Кашель и короткий шум не открывают ячейку. Выбор темы идёт по распознанному тексту: без ясных темы и номинала ячейка не берётся.
- Справа две колонки. «Разговор» — крупные реплики. «Техническое» — события и дословный текст, который модель произнесла, включая чужую фразу. Кнопка «Скопировать дебаг» на технической колонке.
- Колонка «Техническое» по умолчанию скрыта. Кнопка «Техническое» в шапке справа от «Выхода» её открывает и той же кнопкой прячет. Кнопки шапки со значками: пауза, дальше, выход. «Остановить» в шапке сейчас скрыта. «Следующий раунд» рядом со «Скопировать дебаг» заканчивает текущий раунд с тем же счётом: несыгранные ячейки не доигрываются, ведущая объявляет следующий раунд, финал или конец партии.
- Первое приветствие чуть быстрее (`welcomeSpeechSpeed` 1.25): коротко здоровается и зовёт выбрать вопрос. Темы и номиналы не называет: они на табло. Дальше темп обычный. Мостик к финалу может сказать «выберите одну тему», без списка названий.
- Ведущая не произносит ремарку про темы и цены, а шесть и больше тем текущего раунда целиком помещаются на табло над игроками.

Backend не добавлять, пока прямой вызов из браузера сам не откажется. Ключ не писать в код, `.env`, логи, тесты и README.

## Запуск

```bash
npm install
npm run packs
npm run dev
npm test
npx playwright install chromium
npm run look
```

`npm run look` открывает `http://127.0.0.1:5173/?mock=1`. Это заглушка ведущей без ключа и без запроса к OpenAI: можно нажать «Начать игру» и посмотреть экран. Живой голос по-прежнему только с настоящим ключом, без `?mock=1`.

Dev-сервер слушает сеть на порту 5173, чтобы открыть его с планшета.

Живой сайт: https://roginvs.github.io/aisigame/. Продакшен-сборка ставит Vite `base` `/aisigame/`, чтобы пакеты и портрет открывались с адреса проекта. `npm run dev` и `npm run look` остаются на `/`. Pull request и push в `master` проверяет `.github/workflows/ci.yml` (`npm ci`, `npm test`, `npx tsc -b`). Push в `master` ещё собирает сайт в `.github/workflows/pages.yml`: те же проверки, затем `npm run build`, и публикует Pages.

## Куда класть код

- `src/game/machine.ts` — правила, таймеры, счёт, раунды и финал.
- `src/game/savedGame.ts` — снимок партии в `localStorage` (`aisigame.game`), без ключа API.
- `src/game/siq.ts` — разбор `.siq` / `content.xml`.
- `src/game/pack.ts` — поиск вопроса в текущем раунде.
- `src/game/controller.ts` — связка машины и голоса.
- `src/realtime/client.ts` — WebRTC и data channel, без React.
- `src/realtime/mockClient.ts` — заглушка ведущей для `?mock=1`, без ключа и без сети.
- `src/ui` — только отображение и клики.
- `src/options.ts` — длительности партии.
- `src/config.ts` — модель, голос и адрес API.

React не хранит игровые правила. Модель не меняет счёт сама: только function calling, аргументы проверяет машина.
